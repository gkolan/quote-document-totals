# Support

Use the structured GitHub issue forms for reproducible bugs, feature proposals, and questions about the public configuration guides. Search existing issues first and identify the installed tag or full commit SHA.

This repository does not currently promise response or resolution times. The owner must select a sustainable public support policy before describing a release as supported. Production incidents remain the installing organization's responsibility unless a separate written support agreement says otherwise.

Do not use a public issue for a possible security problem. Follow [SECURITY.md](SECURITY.md) and use GitHub private security reporting when it is enabled. Never submit credentials, access tokens, private keys, customer wording, Quote payloads, org URLs, user names, debug logs containing record values, or unredacted screenshots.

For configuration questions, include:

- the repository tag or commit;
- Salesforce API and CPQ versions;
- the public guide and exact step followed;
- safe diagnostic codes and redacted findings; and
- the synthetic fixture and expected result when behavior is disputed.

Questions about Salesforce CPQ licensing, third-party document tools, commercial pricing decisions, legal wording, production access, and organization-specific automation belong with the relevant product vendor or the installing organization's owner.
