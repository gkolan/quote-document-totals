# Plain-English glossary for this series

**Who this is for:** anyone reading any of the six files in these two folders — [`quote-document-totals-creation-pipeline/`](.) and [`../quote-document-totals-row-by-row/`](../quote-document-totals-row-by-row/) — who wants a plain definition of a Salesforce term without leaving the page they're on. You don't need to memorize this. Keep it open in another tab and come back to it whenever a term feels unfamiliar.

Every term below is real Salesforce terminology (not made up for this project), explained without assuming you already know other Salesforce terms.

| Term | Plain-English meaning |
|---|---|
| **Object** | A category of thing Salesforce keeps records of — like a filing cabinet drawer labeled "Quotes" or "Accounts." `SBQQ__Quote__c` (Quote), `Quote_Document_Table__c`, and `Quote_Document_Row__c` are all objects used in this framework. |
| **Record** | One single entry inside an object — one specific Quote, one specific generated table, one specific row. If the object is the filing cabinet drawer, a record is one folder inside it. |
| **Field** | One piece of information stored on a record — like one line on a form. `Table_Code__c` and `Amount_Net__c` are both fields. |
| **`__c` at the end of a name** | Means "Custom" — this object or field was built specifically for this org, rather than coming standard with Salesforce. You'll see it on almost every field and object name in this framework. |
| **`__mdt` at the end of a name** | Means this is a **Custom Metadata Type**, not a regular object — see below. |
| **`__r` in the middle of a name** | Means "relationship" — it's a way of reaching across from one record to a *related* record's field, the way you might write "my sister's phone number" instead of just "phone number." You'll see this in field paths like `SBQQ__Product__r.Family`. |
| **Custom Metadata Type** | A special kind of object used for **settings**, not everyday business data. Regular users never create or edit these records — an admin or developer sets them up once (usually as part of a deployment), and other automated processes read them afterward. Explained in full, with an analogy, in [01-custom-metadata-the-blueprint.md](01-custom-metadata-the-blueprint.md) §1. |
| **Apex** | Salesforce's own programming language, written by a developer and deployed into the org — the thing that actually performs the work of creating, checking, and saving records. You do not need to read or write Apex to use this framework as an admin; this whole series explains what it does in plain English instead. |
| **Flow** | Salesforce's point-and-click automation builder — an admin arranges screens, actions, and decisions visually, without writing code, to give a user a guided, clickable process (like a button that walks someone through a task). |
| **Deploy / Deployment** | The act of moving a change — new metadata records, new Apex code, a new Flow — from a development or testing environment into the org where people actually work. This is how Custom Metadata records and Apex code both get into the system in the first place; neither one is "typed in" by a regular user the way a Quote is. |
| **Query** | A request to Salesforce asking for a specific set of records back — for example, "give me this Quote and every quote line that belongs to it." Apex code runs queries to read data before it can act on it. |
| **Save / Insert** | The action of actually writing a new record permanently into Salesforce, the same way clicking "Save" on a form does. Apex code builds records "in memory" first (meaning: temporarily, not yet written down anywhere) and only afterward tells Salesforce to insert them for real. |
| **Lookup field** | A field on one record that points to a different, related record — similar to a hyperlink. `Quote_Line__c` on a row is a lookup field pointing at the one quote line that row represents. |
| **Master-Detail relationship** | A stricter version of a lookup, where the "child" record (the Detail) cannot exist without its "parent" record (the Master), and deleting the parent automatically deletes every child along with it. `Quote_Document_Row__c` records are Master-Detail children of `Quote_Document_Table__c` — delete a table, and its rows are automatically deleted too, with no extra step needed. |
| **Picklist** | A field where the user is shown a dropdown list and can only pick from pre-set options — Salesforce itself enforces which values are allowed. **Not every field that looks like it has "a fixed list of choices" is actually a true picklist** — some are plain text fields where the *list of valid values* is enforced by Apex code instead of by Salesforce itself. This series is careful to say which is which, because it changes what happens if you type something unexpected: a real picklist won't let you save a bad value; a text field enforced by Apex will let you save it, and only show an error the next time generation runs. |
| **Text field** | A field that accepts freely typed text, with no built-in list of choices. Several fields in this framework are text fields whose *valid* values are documented and checked by Apex, even though they're not true picklists — see the Picklist row above. |
| **Checkbox field** | A field that's simply on or off — `true` or `false`. `Is_Active__c` and `Show_Details__c` are both checkboxes. |
| **Number field** | A field that stores a plain number, with no currency symbol or special formatting. `Level__c` and `Display_Order__c` are both Number fields. |
| **Currency field** | A field that stores a dollar (or other currency) amount, shown with the appropriate currency symbol and formatting. Every `Amount_*` field in this framework is a Currency field. |
| **Formula field** | A field whose value is automatically calculated by Salesforce from other fields, rather than typed in by anyone — it can never drift out of sync, because it's recalculated every time it's viewed. `Quote_Number__c` is a formula field. |
| **Validation Rule** | A declarative (no-code) rule an admin sets up directly on an object that blocks a record from being saved if it doesn't meet a condition — for example, blocking a row from being saved with contradictory settings. |
| **Report / Report Type** | Salesforce's built-in tool for viewing and summarizing records in a table or grid, without needing a custom screen. A **Report Type** is the underlying template that decides which objects and fields are even available to build a report from. |
| **Screen Flow** | A specific kind of Flow meant to be run by a real person, step by step, with actual screens shown along the way — as opposed to a Flow that runs silently in the background with nobody watching. The one Flow in this framework is a Screen Flow. |
| **`@InvocableMethod`** | A label a developer puts on a specific piece of Apex code to make it available as an action a Flow can call, the same way a Flow can call a "Send Email" or "Create Record" action. This is the exact mechanism that lets the one Flow in this framework hand off to Apex. |
| **Transaction** | One complete, all-or-nothing unit of work in Salesforce — either every change inside it is saved, or (if anything goes wrong partway through) none of it is. This is why the framework can promise a quote never ends up "half-updated." |
| **Rollback** | Undoing every change made so far inside the current transaction, as if it never started — what happens automatically if a safety check fails partway through generation. |

If a term shows up in one of the six files that isn't listed here, that's worth flagging back to whoever's maintaining this documentation — this glossary is meant to cover everything used across the series.
