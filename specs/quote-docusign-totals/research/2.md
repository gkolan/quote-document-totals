# Recommended design

Use a **generic grouping engine driven by code-defined table specifications**.

Do not create classes such as:

```text
GroupByIndustry
GroupByIndustryAndFamily
GroupByFamilyAndTransactionType
GroupByPeriodAndFamily
```

That turns every permutation into another class.

Instead, define a table as:

```text
Table definition
  + ordered grouping dimensions
  + amount calculation policy
  + inclusion policy
  + detail grain
  + subtotal policy
  + sorting policy
```

The schema already supports this model: `Group_Dimensions__c` records the ordered dimensions, each row stores its dimension/value/path, the measures are additive, and the inclusion flags distinguish display from arithmetic participation. 

`Group_Dimensions__c` should be an **output of the table definition**, not something Apex parses to determine behavior.

---

# 1. Separate the permutation points

These concerns should not be combined into one giant grouping class.

| Variation                                    | Apex abstraction                  |
| -------------------------------------------- | --------------------------------- |
| Industry, family, transaction type, period   | `GroupingDimension`               |
| Industry → Family versus Family → Industry   | Ordered `List<GroupingDimension>` |
| Group by source line versus bundle parent    | `GroupingValueSource`             |
| Net Change versus ACV versus TCV             | `MeasurePolicy`                   |
| Displayed, hidden-but-counted, informational | `InclusionPolicy`                 |
| One row per quote line versus product        | `DetailPolicy`                    |
| Subtotals at every level versus leaf only    | `SubtotalPolicy`                  |
| Recurring Total, One-Time Total, Tax         | `SectionTotalRule`                |
| Alphabetical versus business-defined order   | `GroupValue.sortRank`             |

That gives you one engine that supports:

```text
No grouping
Product Family
Industry > Product Family
Product Family > Industry
Transaction Type > Product Family
Contract Period > Product Family
Industry > Product Family > Transaction Type
```

Changing the permutation becomes changing the order of a list.

# 2. The core grouping types

The generic layer should not know anything about CPQ fields or DocuSign. It should work against normalized line facts.

```apex
public class QuoteDocumentGroupingModel {
    public enum SubtotalMode {
        NONE,
        LEAF_ONLY,
        EVERY_LEVEL
    }

    public enum DetailMode {
        VISIBLE,
        HIDDEN_BUT_COUNTED
    }

    public enum GroupingValueSource {
        SOURCE_LINE,
        PRICING_OWNER,
        BUNDLE_ROOT
    }

    public interface GroupingDimension {
        String code();
        String traceLabel();
        GroupValue resolve(LineFact line);
    }

    public class GroupValue {
        public String key;
        public String label;
        public Integer sortRank;
        public String sortText;

        public GroupValue(
            String key,
            String label,
            Integer sortRank,
            String sortText
        ) {
            this.key = key;
            this.label = label;
            this.sortRank = sortRank == null ? 1000 : sortRank;
            this.sortText = String.isBlank(sortText) ? label : sortText;
        }

        public static GroupValue unspecified(String label) {
            return new GroupValue(
                '_UNSPECIFIED',
                String.isBlank(label) ? 'Not Specified' : label,
                9999,
                'ZZZZ'
            );
        }
    }

    public class Inclusion {
        public Boolean displayed;
        public Boolean includeInSubtotal;
        public Boolean includeInGrandTotal;

        public Inclusion(
            Boolean displayed,
            Boolean includeInSubtotal,
            Boolean includeInGrandTotal
        ) {
            this.displayed = displayed;
            this.includeInSubtotal = includeInSubtotal;
            this.includeInGrandTotal = includeInGrandTotal;
        }

        public static Inclusion counted(Boolean displayed) {
            return new Inclusion(displayed, true, true);
        }

        public static Inclusion informational() {
            return new Inclusion(true, false, false);
        }
    }

    public class MeasureSet {
        private Map<String, Decimal> values =
            new Map<String, Decimal>();

        public Decimal get(String fieldName) {
            Decimal value = values.get(fieldName);
            return value == null ? 0 : value;
        }

        public void put(String fieldName, Decimal value) {
            values.put(fieldName, value == null ? 0 : value);
        }

        public void add(MeasureSet other) {
            for (String fieldName : other.values.keySet()) {
                put(fieldName, get(fieldName) + other.get(fieldName));
            }
        }

        public MeasureSet copy() {
            MeasureSet result = new MeasureSet();
            result.values.putAll(values);
            return result;
        }

        public void writeTo(SObject target) {
            for (String fieldName : values.keySet()) {
                target.put(fieldName, values.get(fieldName));
            }
        }
    }

    public class LineFact {
        public Id quoteLineId;
        public Id productId;
        public Integer sourceOrder;

        public String productName;
        public String productCode;
        public String productFamily;
        public String transactionType;

        public Inclusion inclusion;
        public MeasureSet measures;

        /*
         * Key format:
         * SOURCE_LINE:PRODUCT_FAMILY
         * BUNDLE_ROOT:PRODUCT_FAMILY
         * SOURCE_LINE:INDUSTRY
         */
        private Map<String, GroupValue> groupingValues =
            new Map<String, GroupValue>();

        public void putGroupValue(
            GroupingValueSource source,
            String dimensionCode,
            GroupValue value
        ) {
            groupingValues.put(
                String.valueOf(source) + ':' + dimensionCode,
                value
            );
        }

        public GroupValue getGroupValue(
            GroupingValueSource source,
            String dimensionCode
        ) {
            return groupingValues.get(
                String.valueOf(source) + ':' + dimensionCode
            );
        }
    }

    public class TableSpec {
        public String tableCode;
        public String tableName;
        public String amountBasis;

        public List<GroupingDimension> dimensions;
        public SubtotalMode subtotalMode;
        public DetailMode detailMode;

        /*
         * See the reconciliation discussion below.
         */
        public Boolean requireTopLevelSubtotalsToEqualGrandTotal;

        public TableSpec(
            String tableCode,
            String tableName,
            String amountBasis,
            List<GroupingDimension> dimensions,
            SubtotalMode subtotalMode,
            DetailMode detailMode
        ) {
            this.tableCode = tableCode;
            this.tableName = tableName;
            this.amountBasis = amountBasis;
            this.dimensions = dimensions;
            this.subtotalMode = subtotalMode;
            this.detailMode = detailMode;
            this.requireTopLevelSubtotalsToEqualGrandTotal = true;
        }

        public String groupDimensionsTrace() {
            List<String> labels = new List<String>();

            for (GroupingDimension dimension : dimensions) {
                labels.add(dimension.traceLabel());
            }

            return String.join(labels, ' > ');
        }
    }
}
```

The important part is that `LineFact` is no longer an `SBQQ__QuoteLine__c`. It is a normalized commercial input.

That lets you unit-test grouping without inserting Quotes, Products, Pricebook Entries, Quote Lines, and CPQ dependencies.

# 3. Reusable dimensions

Most dimensions can be generic attribute dimensions.

```apex
public class QuoteDocumentAttributeDimension
    implements QuoteDocumentGroupingModel.GroupingDimension {

    private String dimensionCode;
    private String dimensionLabel;
    private QuoteDocumentGroupingModel.GroupingValueSource valueSource;
    private Boolean failWhenBlank;

    public QuoteDocumentAttributeDimension(
        String dimensionCode,
        String dimensionLabel,
        QuoteDocumentGroupingModel.GroupingValueSource valueSource,
        Boolean failWhenBlank
    ) {
        this.dimensionCode = dimensionCode;
        this.dimensionLabel = dimensionLabel;
        this.valueSource = valueSource;
        this.failWhenBlank = failWhenBlank;
    }

    public String code() {
        return dimensionCode;
    }

    public String traceLabel() {
        return dimensionLabel;
    }

    public QuoteDocumentGroupingModel.GroupValue resolve(
        QuoteDocumentGroupingModel.LineFact line
    ) {
        QuoteDocumentGroupingModel.GroupValue result =
            line.getGroupValue(valueSource, dimensionCode);

        if (result != null && !String.isBlank(result.key)) {
            return result;
        }

        if (failWhenBlank) {
            throw new GroupingException(
                'Quote Line ' + line.quoteLineId +
                ' has no value for grouping dimension ' +
                dimensionCode
            );
        }

        return QuoteDocumentGroupingModel.GroupValue.unspecified(
            'Not Specified'
        );
    }

    public class GroupingException extends Exception {}
}
```

Then provide factories:

```apex
public class QuoteDocumentDimensions {

            'Product Family',

    }

    public static QuoteDocumentGroupingModel.GroupingDimension transactionType() {
        return new QuoteDocumentAttributeDimension(
            'TRANSACTION_TYPE',
            'Transaction Type',
            SELF,
            true
        );
    }

    public static QuoteDocumentGroupingModel.GroupingDimension contractPeriod() {
        return new QuoteDocumentAttributeDimension(
            'CONTRACT_PERIOD',
            'Contract Period',
            SELF,
            true
        );
    }

    public static QuoteDocumentGroupingModel.GroupingDimension

```

A computed dimension can implement the same interface. For example, a dimension that maps several product families into a higher-level commercial category does not require any change to the grouping engine.

# 5. The generic tree algorithm

Each quote line walks the ordered dimensions and lands in exactly one leaf group.

```apex
for each eligible line:
    currentNode = root

    for each dimension in tableSpec.dimensions:
        groupValue = dimension.resolve(line)
        currentNode = currentNode.getOrCreateChild(
            dimension,
            groupValue
        )

    currentNode.details.add(line)

    if line.includeInSubtotal:
        add its measures to every group node in its path

    if line.includeInGrandTotal:
        add its measures directly to the root grand total
```

The core Apex shape would be:

```apex
public class QuoteDocumentGroupingEngine {
    public static GroupTree build(
        QuoteDocumentGroupingModel.TableSpec spec,
        List<QuoteDocumentGroupingModel.LineFact> sourceLines
    ) {
        GroupNode root = GroupNode.root();
        Set<Id> includedQuoteLineIds = new Set<Id>();

        for (QuoteDocumentGroupingModel.LineFact line : sourceLines) {
            GroupNode current = root;
            List<GroupNode> path = new List<GroupNode>();

            for (
                QuoteDocumentGroupingModel.GroupingDimension dimension
                    : spec.dimensions
            ) {
                QuoteDocumentGroupingModel.GroupValue value =
                    dimension.resolve(line);

                current = current.getOrCreateChild(dimension, value);
                path.add(current);
            }

            current.details.add(line);

            if (line.quoteLineId != null) {
                if (!includedQuoteLineIds.add(line.quoteLineId)) {
                    throw new GroupingException(
                        'Quote Line was added more than once: ' +
                        line.quoteLineId
                    );
                }
            }

            if (line.inclusion.includeInSubtotal) {
                for (GroupNode pathNode : path) {
                    pathNode.subtotal.add(line.measures);
                }
            }

            if (line.inclusion.includeInGrandTotal) {
                root.grandTotal.add(line.measures);
            }
        }

        root.sortRecursively();
        return new GroupTree(spec, root);
    }

    public class GroupingException extends Exception {}

    public class GroupTree {
        public QuoteDocumentGroupingModel.TableSpec spec;
        public GroupNode root;

        public GroupTree(
            QuoteDocumentGroupingModel.TableSpec spec,
            GroupNode root
        ) {
            this.spec = spec;
            this.root = root;
        }
    }

    public class GroupNode {
        public Integer level;
        public String fullPath;
        public String persistedPathKey;

        public QuoteDocumentGroupingModel.GroupingDimension dimension;
        public QuoteDocumentGroupingModel.GroupValue value;

        public Map<String, GroupNode> childrenBySegment =
            new Map<String, GroupNode>();

        public List<QuoteDocumentGroupingModel.LineFact> details =
            new List<QuoteDocumentGroupingModel.LineFact>();

        public QuoteDocumentGroupingModel.MeasureSet subtotal =
            new QuoteDocumentGroupingModel.MeasureSet();

        public QuoteDocumentGroupingModel.MeasureSet grandTotal =
            new QuoteDocumentGroupingModel.MeasureSet();

        public static GroupNode root() {
            GroupNode node = new GroupNode();
            node.level = 0;
            node.fullPath = '';
            node.persistedPathKey = '';
            return node;
        }

        public GroupNode getOrCreateChild(
            QuoteDocumentGroupingModel.GroupingDimension childDimension,
            QuoteDocumentGroupingModel.GroupValue childValue
        ) {
            String segment =
                childDimension.code() + '=' + childValue.key;

            if (!childrenBySegment.containsKey(segment)) {
                GroupNode child = new GroupNode();
                child.level = level + 1;
                child.dimension = childDimension;
                child.value = childValue;
                child.fullPath = String.isBlank(fullPath)
                    ? segment
                    : fullPath + '|' + segment;

                child.persistedPathKey =
                    QuoteDocumentGroupKeys.persistedKey(child.fullPath);

                childrenBySegment.put(segment, child);
            }

            return childrenBySegment.get(segment);
        }

        public void sortRecursively() {
            /*
             * Convert map values to a list and explicitly sort using:
             *
             * 1. GroupValue.sortRank
             * 2. GroupValue.sortText
             * 3. GroupValue.key
             *
             * Never rely on Map iteration order.
             */

            for (GroupNode child : childrenBySegment.values()) {
                child.sortRecursively();
            }

            /*
             * Details should also be sorted deterministically:
             * source order, product code, then Quote Line Id.
             */
        }
    }
}
```

The grouping engine should do **no SOQL and no DML**. It produces a planned tree or planned flat rows.

That separation will make this much easier to reason about than a generator that queries, groups, inserts, and calculates all inside one method.

# 6. Four invariants to settle before implementation

## A. A dimension must be a partition

Every eligible line must resolve to exactly one value for every configured dimension.

Good:

```text
Industry = Life Sciences
Product Family = Analytics
```

Also acceptable:

```text
Industry = _UNSPECIFIED
Product Family = Analytics
```

Not acceptable without a separate allocation model:

```text
Industry = Life Sciences and Healthcare
```

Duplicating one line into two groups would double-count it. Supporting multi-membership would require an allocation percentage or a rule saying which duplicated copy counts. Do not let a dimension return multiple values in version one.

## B. Your two inclusion flags conflict with one stated reconciliation

Your schema allows these to differ:

```text
Include_In_Subtotal__c
Include_In_Grand_Total__c
```

But it also requires:

```text
Grand total =
    sum of level-1 subtotals
    and
    sum of grand-total-included detail rows
```

Those two calculations are guaranteed to match only when the inclusion decisions are equivalent.

For version one, I recommend:

```apex
Include_In_Subtotal__c == Include_In_Grand_Total__c
```

Keep both fields on the object, but have the Apex inclusion policy return only:

```text
Counted:       true / true
Not counted:  false / false
```

Do not introduce subtotal-only or grand-total-only rows yet.

If you later need different values, the table definition must explicitly disable the “level-1 subtotals equal grand total” assertion.

## C. Stable keys must not use display labels

Use:

```text
INDUSTRY=LIFE_SCIENCES|PRODUCT_FAMILY=ANALYTICS
```

Do not use:

```text
Industry=Life Sciences|Product Family=Analytics Solutions
```

Labels can be renamed or translated. Keys must remain stable.

Also, a full path can exceed the current `Group_Key__c` length of 255 characters. Use short normalized group codes, and hash the full path when necessary:

```apex
public class QuoteDocumentGroupKeys {
    public static String persistedKey(String fullPath) {
        if (fullPath.length() <= 255) {
            return fullPath;
        }

        String digest = EncodingUtil.convertToHex(
            Crypto.generateDigest(
                'SHA-256',
                Blob.valueOf(fullPath)
            )
        );

        return 'SHA256:' + digest;
    }
}
```

Keep the full path in memory for generation. Persist the readable value when it fits and the hash when it does not.

## D. Define `Parent_Row__c` semantics precisely

The schema does not fully define whether a subtotal is a child of its own group header or the parent group.

I would use:

| Row                         | Group level | Parent row     |
| --------------------------- | ----------: | -------------- |
| Level-1 group header        |           1 | Blank          |
| Level-2 group header        |           2 | Level-1 header |
| Detail inside level-2 group |           3 | Level-2 header |
| Level-2 subtotal            |           2 | Blank          |
| Level-1 subtotal            |           1 | Blank          |
| Section total               |           0 | Blank          |
| Grand total                 |           0 | Blank          |

Use `Group_Key__c` to associate a subtotal with the group it closes.

`Parent_Row__c` then represents the navigable group hierarchy for headers and details. It does not try to represent the document’s entire flat render stream.

Consequently, the parent-chain-depth assertion should apply to **group headers and details**, not aggregate rows.

# 7. Bundles need two separate decisions

Do not let “bundle handling” become part of the generic tree algorithm.

For every quote line, determine separately:

### Financial owner

Which line contributes the measure?

```text
Parent-priced bundle:
    parent counts
    children do not count

Child-priced bundle:
    parent does not count
    children count
```

### Grouping source

Which product classification should receive the counted amount?

```text
SOURCE_LINE
PRICING_OWNER
BUNDLE_ROOT
```

For example:

```apex
QuoteDocumentDimensions.productFamily()
```

might use the source line, while:

```apex
QuoteDocumentDimensions.bundleRootProductFamily()
```

uses the bundle root.

This distinction matters when the child belongs to a different product family from its bundle parent.

The grouping engine should receive the resolved values. It should not contain CPQ bundle conditions.

# 8. Detail grain is not the same thing as grouping

These are different tables:

```text
Group by Product Family
    one detail row per Quote Line
```

and:

```text
Group by Product Family
    one detail row per Product
```

The second requires a second aggregation layer.

For version one, I would support only:

```text
Detail grain = Quote Line
```

You already deferred `Source_Line_Count__c` until aggregated detail rows exist. That is sensible.

Later, add a `DetailPolicy`:

```apex
public interface DetailPolicy {
    String bucketKey(
        QuoteDocumentGroupingModel.LineFact line
    );

    String sourceGrain();
}
```

Implementations could be:

```text
QuoteLineDetailPolicy
ProductDetailPolicy
BundleDetailPolicy
SubscriptionDetailPolicy
SegmentDetailPolicy
```

Do not implement product-level aggregation implicitly by grouping on Product. A Product group subtotal and a Product-grain detail row may look identical in the document, but they have different traceability semantics.

---

# 9. Section totals should not be group nodes

A grouping hierarchy partitions the source lines.

A section total can be:

```text
Recurring Total
One-Time Total
Tax
Discount
```

Some sections may overlap or may be independently calculated. Therefore, calculate section totals with separate rules after the grouping tree has been built:

```apex
public interface SectionTotalRule {
    String code();
    String displayLabel();

    Boolean includes(
        QuoteDocumentGroupingModel.LineFact line
    );
}
```

Use a dimension when every line belongs to exactly one category and the category is part of the hierarchy.

Use a section rule when the amount is a calculated or potentially overlapping slice.

# 10. Platform event orchestration

I agree with using a platform event as a refresh request, with one major change:

> Do not think of it as “generate once for every save.” Think of it as “the current generated projection may be stale.”

Define something like:

```text
Quote_Document_Refresh_Requested__e

Quote_Id__c    Text(18)
Reason__c      Text(80)
```

Configure the event’s publish behavior as **Publish After Commit**, so the subscriber queries committed Quote and Quote Line state. Platform events use an at-least-once model, meaning duplicates are possible, so regeneration must remain idempotent. ([Developer][1])

Publish when:

```text
Quote Line inserted
Quote Line deleted or undeleted
Relevant Quote Line field changed
Relevant Quote field changed
CPQ calculation completed
User explicitly requests regeneration
```

Do not publish because:

```text
Quote document status changed
Generated On changed
An unrelated Quote description changed
A document row was inserted
```

Create one impact detector responsible for deciding whether a change matters.

```apex
public class QuoteDocumentImpactDetector {
    public static Boolean quoteLineChanged(
        SBQQ__QuoteLine__c currentLine,
        SBQQ__QuoteLine__c previousLine
    ) {
        if (previousLine == null) {
            return true;
        }

        return
            currentLine.SBQQ__Product__c !=
                previousLine.SBQQ__Product__c
            ||
            currentLine.SBQQ__Quantity__c !=
                previousLine.SBQQ__Quantity__c
            ||
            currentLine.SBQQ__NetTotal__c !=
                previousLine.SBQQ__NetTotal__c;

        /*
         * Add every field that affects:
         * eligibility, grouping, transaction classification,
         * amount basis, bundles, display, or totals.
         */
    }
}
```

The publisher should deduplicate Quote IDs within the transaction:

```apex
public class QuoteDocumentRefreshPublisher {
    private static Set<Id> publishedQuoteIds = new Set<Id>();

    public static void request(Set<Id> quoteIds, String reason) {
        List<Quote_Document_Refresh_Requested__e> events =
            new List<Quote_Document_Refresh_Requested__e>();

        for (Id quoteId : quoteIds) {
            if (quoteId == null || !publishedQuoteIds.add(quoteId)) {
                continue;
            }

            events.add(
                new Quote_Document_Refresh_Requested__e(
                    Quote_Id__c = quoteId,
                    Reason__c = reason
                )
            );
        }

        if (!events.isEmpty()) {
            EventBus.publish(events);
        }
    }
}
```

The event should carry the Quote ID, not calculated amounts or grouping values. The subscriber should always query the latest committed state.

# 11. Do you still need Queueable?

Not initially.

A platform-event Apex trigger already runs asynchronously. Calling a Queueable from it adds another hop without necessarily providing more capacity.

Start with:

```apex
trigger QuoteDocumentRefreshEventTrigger
    on Quote_Document_Refresh_Requested__e (after insert) {

    Set<Id> quoteIds = new Set<Id>();

    for (
        Quote_Document_Refresh_Requested__e eventRecord
            : Trigger.new
    ) {
        if (!String.isBlank(eventRecord.Quote_Id__c)) {
            quoteIds.add((Id) eventRecord.Quote_Id__c);
        }
    }

    QuoteDocumentGenerationService.generate(quoteIds);
}
```

However, configure the platform-event subscriber batch size deliberately. Platform-event Apex triggers default to batches of up to 2,000 events and run as Automated Process unless you configure a different subscriber user. A document generator that inserts hundreds of rows per Quote should not accept the default batch blindly. I would start with a batch size of **1 to 5 Quotes**, measure the row and CPU volume, and increase only when justified. ([Developer][2])

A configured subscriber user is preferable when you need predictable:

```text
Created By
locale-dependent labels
debug logs
permissions
audit ownership
```

## When Queueable becomes useful

Add Queueable later when you need:

```text
A deliberate delay so repeated saves coalesce
Chaining because one Quote exceeds one transaction
Retries with a finalizer
Different resource isolation
More explicit job monitoring
```

Do not enqueue one Queueable inside a loop over platform events. A platform-event trigger is already an asynchronous transaction, and asynchronous transactions normally have a one-Queueable-enqueue limit. Salesforce also supports duplicate Queueable signatures to reduce duplicate jobs, but that is additional protection—not a replacement for idempotent generation. ([Developer][3])

# 12. Serialize generation for the same Quote

Two events for the same Quote can still arrive close together.

At the start of generation, lock the Quote:

```apex
List<SBQQ__Quote__c> quotes = [
    SELECT
        Id,
        CurrencyIsoCode
    FROM SBQQ__Quote__c
    WHERE Id IN :quoteIds
    ORDER BY Id
    FOR UPDATE
];
```

`FOR UPDATE` is specifically intended to prevent race conditions between transactions updating the same records. ([Developer][4])

Then both duplicate requests are safe:

```text
Request A locks Quote
Request A regenerates
Request A commits

Request B acquires lock
Request B queries current state
Request B regenerates the same current result
```

The second generation is unnecessary work, but it is correct. A source fingerprint can eliminate that extra work later.

# 13. Generation service sequence

The service should follow this order:

1. Lock the Quotes.
2. Query all required Quote Lines once.
3. Normalize Quote Lines into `LineFact` records.
4. Build every table completely in memory.
5. Run arithmetic and uniqueness assertions in memory.
6. Only after validation, delete and replace persisted rows.
7. Insert group headers by increasing depth.
8. Insert details, subtotals, section totals, and grand totals with resolved parent IDs.
9. Write table measures, count, version, timestamp, and Complete status.

Building and validating before deleting existing rows matters. A classification or grouping defect should not destroy the previous complete data before you discover the error.

The service should look roughly like:

```apex
public class QuoteDocumentGenerationService {
    public static void generate(Set<Id> quoteIds) {
        if (quoteIds == null || quoteIds.isEmpty()) {
            return;
        }

        List<SBQQ__Quote__c> lockedQuotes = [
            SELECT Id, CurrencyIsoCode
            FROM SBQQ__Quote__c
            WHERE Id IN :quoteIds
            ORDER BY Id
            FOR UPDATE
        ];

        Map<Id, List<QuoteDocumentGroupingModel.LineFact>>
            factsByQuote =
                QuoteDocumentLineFactSelector.load(
                    new Map<Id, SBQQ__Quote__c>(lockedQuotes).keySet()
                );

        List<QuoteDocumentGroupingModel.TableSpec> definitions =
            QuoteDocumentDefinitionRegistry.all();

        for (SBQQ__Quote__c quoteRecord : lockedQuotes) {
            List<PlannedTable> plans = new List<PlannedTable>();

            for (
                QuoteDocumentGroupingModel.TableSpec definition
                    : definitions
            ) {
                QuoteDocumentGroupingEngine.GroupTree tree =
                    QuoteDocumentGroupingEngine.build(
                        definition,
                        factsByQuote.get(quoteRecord.Id)
                    );

                PlannedTable plan =
                    QuoteDocumentRowPlanner.plan(
                        quoteRecord,
                        definition,
                        tree
                    );

                QuoteDocumentAssertions.validate(plan);
                plans.add(plan);
            }

            QuoteDocumentRepository.replaceAll(
                quoteRecord,
                plans
            );
        }
    }
}
```

The class responsibilities remain clean:

```text
Selector          Queries data
Fact Factory      Understands CPQ
Definition        Describes desired table
Grouping Engine   Builds hierarchy and totals
Row Planner       Produces final row order
Assertions        Reconciles amounts
Repository        Performs DML
Event Publisher   Detects stale projections
```

# 14. Minimum test matrix

| Scenario                               | Expected result                             |
| -------------------------------------- | ------------------------------------------- |
| Empty dimension list                   | Details followed by grand total             |
| Product Family                         | One level of groups                         |
| Industry → Family                      | Correct nested paths and subtotals          |
| Family → Industry                      | Different hierarchy from the same lines     |
| Same family under two industries       | Two distinct full group keys                |
| Blank industry                         | `_UNSPECIFIED` group or explicit failure    |
| Input lines supplied in random order   | Identical final `Display_Order__c`          |
| Hidden-but-counted child               | Not displayed; included in both totals      |
| Displayed informational child          | Displayed; included in neither total        |
| Parent-priced bundle                   | Parent counts; child does not               |
| Child-priced bundle                    | Child counts; parent does not               |
| Negative cancellation                  | Remains negative at every aggregation level |
| Duplicate Quote Line added twice       | Generation fails                            |
| Group path over 255 characters         | Stable hashed persisted key                 |
| Duplicate platform events              | Same final persisted result                 |
| One grouping value maps to two buckets | Generation fails                            |
| Top-level subtotal versus grand total  | Exact equality in version one               |

# My v1 recommendation

Implement these constraints first:

```text
Static Apex definition registry
Ordered dimensions
One bucket per line per dimension
Quote Line detail grain only
Subtotals at every configured level
Include In Subtotal = Include In Grand Total
Separate section-total rules
Stable normalized path keys
Direct platform-event subscriber execution
Small subscriber batch
Quote lock using FOR UPDATE
```

That is enough flexibility for the current permutations without creating a framework so abstract that it becomes hard to maintain. Later, custom metadata can construct the same `TableSpec` objects; the grouping engine itself will not need to change.
